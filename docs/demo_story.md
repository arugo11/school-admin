# Demo Story

## One-Sentence Pitch
答案を撮るだけで、生徒ごとの弱点と今夜の宿題候補が出て、最後は講師が軽く整えて確定できる。

## Why It Matters
- 塾では授業前の短時間に6人分の答案を見切るのが難しい。
- 点数だけでは、符号ミス、解き直し不足、宿題負荷の重さが埋もれる。
- このデモは、教師を置き換えるのではなく、教師の初動を速くする。

## What Judges Should Notice
- 現場価値: 紙の答案という現実入力を起点にしている。
- 技術実装: OCR -> 正規化 JSON -> LLM/ルール -> 講師承認の一貫フロー。
- デモ体験: 6人一覧から主役1人に入って、2分で宿題承認まで見せられる。
- 発展性: 今回は Azure 推論だが、I/O 境界はローカルに残しており、将来は OCR コンテナやローカル推論へ寄せやすい。

## Edge Narrative
- 今回の本線は Azure Vision Read と Azure OpenAI を使う。
- 理由はハッカソンの成功率を優先するため。
- ただし、ローカル Web/API が制御境界を持っているので、将来は次を edge 側に寄せられる。
  - OCR 前処理
  - OCR 実行
  - 分析モデル
  - 教室内キャッシュ

## Main Student
- `s-03` Yuna Kobayashi
- よく頑張るが、惜しい符号ミスと浅い解き直しで点が伸び切らない。
- ここに短くやり切れる宿題を出すのがデモの感情的な核になる。
